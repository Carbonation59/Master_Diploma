## О проекте

**Тема:** «Метод анализа архитектуры программного обеспечения на поиск уязвимостей»

Работа посвящена разработке автоматизированного метода обнаружения структурных уязвимостей (антипаттернов) в архитектуре программного обеспечения. Метод основан на представлении архитектуры в виде графа и применении алгоритмов его анализа.

### Ключевые понятия

- **Архитектурная уязвимость** — структурное свойство системы, повышающее вероятность отказа, снижающее масштабируемость или создающее скрытые риски сопровождения.
- **Модель C4 / Structurizr** — стандарт иерархического описания архитектуры (SoftwareSystem → Container → Component → DeploymentNode), используемый как входной формат.
- **Neo4j** — графовая СУБД, в которой хранится и анализируется архитектурный граф с плагинами APOC и Graph Data Science (GDS).

### Реализованные виды анализа

| Анализ | Описание | Инструмент |
|---|---|---|
| Циклические зависимости | Поиск циклов в графе зависимостей компонентов | `apoc.nodes.cycles` |
| Единые точки отказа (SPOF) | Вершины-шарниры, удаление которых разрывает граф | `gds.articulationPoints` |
| «Божественные» объекты | Компоненты с чрезмерно высокой степенью связности (top 5%) | `gds.degree` |
| «Бутылочные горлышки» | Минимальная пропускная способность, суммарная задержка и надёжность пути | Кратчайший путь + `apoc.agg.product` |
| Скрытое совместное использование инфраструктуры | Несколько независимых систем на одном DeploymentNode | Обход `[:Child*1..]` |
| Нарушение сетевого периметра | Компоненты в DMZ-зоне без требуемых свойств технологий | Обход `[:Child*]` + `[:Deploy]` |

## Запуск

### 1. Запуск всех сервисов

```bash
docker compose up --build
```

После запуска будут доступны:

| Интерфейс | URL |
|---|---|
| Веб-приложение (анализ архитектуры) | http://localhost:3001 |
| REST API (Swagger UI) | http://localhost:8083/swagger-ui/index.html |
| Neo4j Browser | http://localhost:7474 |

Логин/пароль для Neo4j: `neo4j` / `password`

### 2. Остановка

```bash
docker compose down
```

Чтобы также удалить данные Neo4j:

```bash
docker compose down -v
```

## Использование

### Загрузка архитектуры

1. Откройте http://localhost:3001
2. Перейдите на вкладку **Upload**
3. Выберите файл в формате Structurizr JSON (описание workspace по модели C4)
4. Выберите тип графа:
   - **Local** — изолированный граф одной системы (очищает предыдущую версию)
   - **Global** — дополнение общего многосистемного графа

Примеры тестовых файлов находятся в папке `tests/`.

### Визуализация

Вкладка **Visualize** — интерактивный граф с возможностью выполнять произвольные Cypher-запросы.

### Анализ

На вкладке **Analysis** доступны все шесть видов проверок. Для каждой можно настроить:
- `graphTag` — тег системы/графа
- `nodeTypes` — типы вершин (например, `Container`, `Component`)
- `relTypes` — типы рёбер (например, `Relationship`)
- `nodeIdentifiers` — DSL-идентификаторы конкретных узлов

Результаты можно скачать в формате JSON.

## REST API

Базовый URL: `http://localhost:8083/api/v1`

### Загрузка графа

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/graph/local/json` | Загрузить систему как локальный граф |
| `POST` | `/graph/json` | Добавить систему в глобальный граф |
| `GET` | `/elements` | Выполнить Cypher-запрос (заголовок `CYPHER-QUERY`) |

### Анализ

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/analyse/cycles` | Циклические зависимости |
| `GET` | `/analyse/singlepoints` | Единые точки отказа |
| `GET` | `/analyse/godelements` | «Божественные» объекты |
| `GET` | `/analyse/pathcapacity` | Пропускная способность пути |
| `GET` | `/analyse/criticalinfrastructure` | Скрытое совместное использование инфраструктуры |
| `GET` | `/analyse/perimeterviolation` | Нарушение сетевого периметра |

Полная документация API доступна через Swagger UI: http://localhost:8083/swagger-ui/index.html
